Google Business Attribute Gap Analyzer
1. Background Information (The "Why")
Local businesses often lose potential customer traffic and revenue because their Google Business profiles are incomplete. They frequently do not know which specific categorical attributes (e.g., "wheelchair accessible," "women-owned," "outdoor seating") are available for their Primary Business Category. This system acts as a specialized consultant agent. It will take a business name, identify its primary category, query all possible attributes for that category, compare them against the business's actual public profile, and output an "Attribute Gap Analysis" to help the business optimize its search presence.
This project aligns with the "Agents for Business" track by solving a compelling business problem with revenue on the line
.
2. Full Technical Design
Agent Architecture: Multi-Agent System (ADK) To ensure the system is manageable and efficient, the workflow is split across an ADK sub-agent pipeline:
- Search Agent: Takes the business name input, queries the Google Places API, and finds the specific Google Place ID and Primary Category.
- Data Agent: Connects to a local MCP Server (launched using `sys.executable` to ensure container compatibility) to fetch the "Actual Attributes" and "Possible Attributes" for the category, saving them to the session state.
- Analyst Agent: Compares the datasets, calculates the missing opportunities, calls `write_report` to save the YAML report, and always displays the generated YAML report directly in the chat response to the user for consistent UI presentation.

Tooling Integration: MCP Server
The Data Agent interacts with the Google Places API via an MCP Server. To prevent API errors:
- The API requests specify the correct Place Details (New) camelCase field names, including `"goodForChildren"` (rather than the invalid `"goodForKids"`).
- Outbound server-side requests are made using an unrestricted API key (restricted only by API, not HTTP referrers).
- The deployment configuration (`Dockerfile`) explicitly copies `mcp_server.py` into the container image root so it is available to the Python runtime.

Testing UI: Antigravity Built-in Browser
To verify the user interface of the gap analyzer, the agent will utilize Antigravity's built-in Chrome browser to autonomously run localhost and test visual UI changes. This must be executed within Antigravity's isolated, sandbox-like Chrome profile to prevent context leakage or unauthorized live operations.
Security Features: Zero-Trust Guardrails
Context Hygiene: To prevent "Context Hallucination" risks, rigorous Context Hygiene must be implemented
. A dynamic ContextResolver will use regex to intercept incoming tool calls and replace any PII with bracketed placeholders (e.g., [[BUSINESS_OWNER_EMAIL]]) so sensitive strings are sterilized dynamically
.
Policy Server: A hybrid policy server will intercept actions before they hit external systems
. It will use Structural Gating (deterministic rules in a policies.yaml file) to restrict tool access, and Semantic Gating (an LLM referee) to evaluate if the action's intent violates privacy guidelines
.

4. Data Schema
Note: The following schema defines the output of the Analyst Agent. It is formatted in YAML to maximize parsing accuracy for nested data
.
attribute_gap_report:
  business_name: string
  primary_category: string
  analysis:
    actual_attributes_used:
      - attribute_name: string
    possible_category_attributes:
      - attribute_name: string
    missing_opportunities:
      - attribute_name: string
        recommendation_impact: string
5. Behavior-Driven Development (BDD) Scenarios
Scenario 1: Successful Gap Analysis
Given the user inputs the business name "Downtown Cafe"
When the Search Agent identifies it as category "Coffee Shop"
And the Data Agent retrieves 15 possible attributes via the MCP Server but finds the business only uses 3
Then the Analyst Agent must output a gap report listing the 12 missing attributes with recommendations based on the YAML schema.
Scenario 2: Security Interception via Policy Server
Given the agent retrieves data that includes the private phone number or owner email of the business
When the Analyst Agent attempts to write this to the final public report using the write_report tool
Then the Semantic Gating layer of the Policy Server must intercept the action, flag it as a PII policy violation, and return a "Policy Violation" message to the agent to force a self-correction
.
Scenario 3: UI Testing via Antigravity Browser
Given the developer has implemented a new submit button on the local web interface
When the agent is instructed to verify the UI
Then the agent must launch the Antigravity sandboxed browser, navigate to localhost, and simulate a user clicking the submit button to ensure it triggers the Search Agent
.
